# Development Workbench Skill

Навык для создания и доработки приложений. Помогает найти ответственный участок кода, не наслаивать новую реализацию поверх старой, учитывать права доступа и проверять затронутые сценарии.

## Установка

Скопируйте содержимое репозитория в `~/.codex/skills/development-workbench-skill`. В Codex напишите `$development-workbench-skill` и задачу обычными словами. Все инструкции навыка находятся в [SKILL.md](SKILL.md).

## Как попросить

- `$development-workbench-skill Создай экран управления курсами. Сначала посмотри существующую структуру и используй подходящие готовые компоненты.`
- `$development-workbench-skill Найди, почему преподаватель не видит попытки. Исправь причину и проверь соседние роли.`
- `$development-workbench-skill Разбери модуль документов: покажи дублирующие пути, затем аккуратно замени старый путь и проверь сценарий.`
- `$development-workbench-skill Проверь интерфейс: согласованность, мобильный вид, клавиатуру и состояния ошибок.`

Указывать внутренние команды и имена файлов не нужно. Навык изучит проект и задаст короткий вопрос только при важной неопределённости. Проверки выбираются по рискам задачи и правилам проекта. [Правила «как не надо / как надо»](references/development-rules.md) объясняют основные решения.

## Состав

- `SKILL.md` — вход и выбор режима работы.
- `references/` — создание, архитектура, замена старого кода, диагностика, frontend, backend, интерфейс, безопасность и проверки.
- `scripts/` — вспомогательные проверки границ модулей и остатков старого пути; они не заменяют тесты проекта.
- `tests/` — быстрая проверка вспомогательных скриптов: `node tests/smoke.mjs`.

Навык не привязан к RTM или определённой структуре папок. Правила конкретного проекта имеют приоритет.
