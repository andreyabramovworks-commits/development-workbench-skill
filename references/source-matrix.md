## Resolved overlaps

| Overlap | Decision in this skill |
| --- | --- |
| KodMaster and megastep review checklists | One evidence-based review process in `review.md`; findings need impact and reproducibility. |
| ghalex vertical interview versus spec writing | Inspect the actual code first; ask only unresolved choices; create a spec when complexity warrants it. |
| ghalex React rules versus Vercel and danielteles guidance | Project stack and existing conventions win; React rules are conditional on actual versions and tools. |
| KodMaster, megastep, and danielteles testing instructions | One risk-based verification process; no required test for every trivial reversible edit. |
| Anthropic, LeorickCoder, and Vercel design approaches | One sequence: understand product → choose direction → define reusable tokens where needed → implement → inspect real UI. |
| Source skills' approval or deployment procedures | User instructions and project rules determine authorization and release workflow. The new skill does not impose external approval gates. |
| Feature-Sliced Design layers versus this skill's default structure | Use `app / features / domain / shared` as responsibility map for new applications, without creating empty folders. Existing apps migrate only where a change justifies it. |

## Exclusions

`ghalex/*-setup`, Next.js and Vercel deployment guides, unrelated iOS/ads skills in the large megastep collection, slide and banner skills, and generic visual effect skills do not improve the core cross-stack workflow. They were inventoried but not copied. The new skill can be extended for a concrete technology after evidence of need.
